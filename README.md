# The Twelve - World Cup 2026 Fantasy

The Twelve is a full-stack fantasy contest app for the FIFA World Cup 2026. Public users build a
12-player roster, submit a team name and display name, then compete on a public leaderboard scored
from imported player stats. Admins manage imports, teams, scores, and audited adjustments.

Code is the source of truth for behavior. Use [docs/](./docs/README.md) as a lightweight code map
and [docs/deployment.md](./docs/deployment.md) for Railway deployment.

## Quick Start

```bash
vp install
vp run dev
```

Open `http://localhost:3000`. Development admin login:

```text
admin@wc2026.local / WC2026Admin!
```

With no `DATABASE_URL`, the app uses an in-memory store seeded from checked-in fixtures and sample
teams. Local data resets on restart.

## Common Commands

```bash
vp check                 # format, lint, and typecheck
vp test                  # Vitest suite
vp build                 # production build
vp run generate-routes   # regenerate src/routeTree.gen.ts after route-file changes
vp run db:generate       # create Drizzle migrations after schema changes
vp run db:migrate        # apply migrations to DATABASE_URL
```

Use Vite+ (`vp`) first. Package scripts exist mostly so Railway/Nixpacks and tooling have stable
entry points.

## App Surfaces

| Route                           | Purpose                                     |
| ------------------------------- | ------------------------------------------- |
| `/`                             | Public team builder                         |
| `/leaderboard`                  | Public standings and roster breakdowns      |
| `/teams/:teamId`                | Public team detail                          |
| `/teams/:teamId/edit?token=...` | Public edit-link flow until tournament lock |
| `/about`                        | In-app rules and scoring reference          |
| `/admin/*`                      | Better Auth guarded admin dashboard         |
| `/api/*`                        | Route-file APIs under `src/routes/api.*.ts` |
| `/api/health`                   | Deployment health check                     |

## Technical Map

```text
src/domain/            roster validation, scoring, regions, positions, leaderboard ranking
src/routes/            TanStack route components and API handlers
src/components/        local React UI components
src/server/services/   reusable business services for teams, scores, imports, admin actions
src/server/db/         DataStore contract, memory store, Drizzle schema, PostgreSQL store
src/server/imports/    fixture-backed importers, raw artifact cache, import logging
src/server/auth/       Better Auth setup and admin guards
src/server/env.ts      runtime config and production startup checks
```

Important generated/runtime files:

- `src/routeTree.gen.ts` is generated by TanStack Router. Do not hand-edit it.
- `.data-cache/` stores raw import artifacts locally and is gitignored.
- `.env.example` lists runtime configuration.
- `nixpacks.toml` defines Railway build/start behavior.

## Runtime Notes

- Roster rules live in `src/domain/validation.ts` and are shared by client and server.
- Scoring rules live in `src/domain/scoring.ts`; tests cover deterministic point totals.
- Group labels come from imported/fixture tournament data, not hard-coded validation constants.
- Public edit tokens are returned once and stored only as SHA-256 hashes.
- Production persistence is PostgreSQL through `DATABASE_URL`; local development defaults to memory.
- Current imports use checked-in fixtures. Live FIFA/FBref collection still needs source and terms
  review before being wired into production.

## Deployment

Railway deployment is not complete yet. The runbook is in
[docs/deployment.md](./docs/deployment.md).

At a high level:

1. Provision Railway PostgreSQL and set app variables from `.env.example`.
2. Run Drizzle migrations against `DATABASE_URL`.
3. Deploy with `nixpacks.toml`.
4. Verify `GET /api/health`.
5. Log into `/admin` and run the import pipeline to load production data.
